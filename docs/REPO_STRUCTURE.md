# Repository structure

This repository holds **static assets** (JSON content and SVG images) meant to be served like a CDN: clients can fetch files by path and use **`manifest.json`** to discover paths, sizes, content hashes, and version numbers for cache invalidation.

---

## Root layout

| Item | Role |
|------|------|
| **`assets/`** | All publishable content and images (see below). |
| **`manifest.json`** | Machine-readable index of every tracked asset: paths, SHA-256 hashes, byte sizes, and per-file or per-group versions. Regenerated by the script; commit it when assets change. |
| **`generate_manifest.py`** | Builds `manifest.json` by walking `assets/`, hashing files, and bumping versions when content changes. |
| **`.gitignore`** | Ignores macOS junk (e.g. `.DS_Store`). |

There is no application server in this repo; it is **data + a manifest generator** only.

---

## `assets/content/`

Structured text data for the product (categories, subcategories, scripts, and situations).

### `assets/content/config/`

- **`premium_config.json`** — Lists which category, subcategory, and script IDs are treated as premium (gating / entitlements).

### Locale folders (`en`, `tr`, …)

Each locale is a directory whose name is the locale code (currently **`en`** and **`tr`**). Inside each locale:

| File | Typical purpose |
|------|-----------------|
| **`categories.json`** | Top-level groupings (id, title, icon, sort order, visibility, etc.). |
| **`subcategories.json`** | Nested groupings under categories. |
| **`scripts.json`** | The main script content payload for that language (large JSON). |
| **`situations.json`** | Scenario prompts for script-selection practice; each situation references script ids for the correct answer and distractors. |

The manifest generator only includes locale folders that sit next to `config` under `assets/content/` and that contain the expected JSON files.

---

## `assets/images/`

Binary (vector) artwork referenced by the content or UI.

| Directory | Contents |
|-----------|----------|
| **`category_images/`** | SVGs for categories / subcategories (filenames usually align with content ids, e.g. `greet-goodbye.svg`). |
| **`script_images/`** | SVGs tied to specific scripts or script groups. |

Each subdirectory becomes an **`images`** entry in `manifest.json`. Folder names use underscores on disk (e.g. `category_images`); manifest keys drop underscores (e.g. `categoryimages`) for the group id.

---

## How `generate_manifest.py` relates to `manifest.json`

1. **Config** — If `assets/content/config/premium_config.json` exists, it is recorded under `content.config.premium` with path, hash, size, and version.

2. **Locales** — For each subdirectory of `assets/content/` except `config`, the script looks for `categories.json`, `subcategories.json`, `scripts.json`, and `situations.json` and adds them under `content.locales.<locale>.<key>`.

3. **Images** — For each subdirectory of `assets/images/`, every file is hashed; per-file versions bump when that file’s hash changes; the group’s aggregate version bumps if any file in the group changed.

4. **Version stability** — If a file’s hash is unchanged from the previous manifest, its **version number is preserved** so unchanged assets do not get spurious version bumps.

Run from the repo root:

```bash
python3 generate_manifest.py
```

That overwrites **`manifest.json`** with a new `lastUpdated` timestamp (UTC ISO-8601 with a `Z` suffix).

---

## Typical workflow when changing assets

1. Edit JSON under `assets/content/` and/or SVGs under `assets/images/`.
2. Run `python3 generate_manifest.py`.
3. Commit both the asset changes and the updated `manifest.json` so clients see consistent hashes and versions.

## Mental model

```text
ssc_cdn/
├── manifest.json              # Index for clients (hashes, versions, paths)
├── generate_manifest.py       # Regenerates manifest from assets/
└── assets/
    ├── content/
    │   ├── config/            # Cross-locale config (e.g. premium ids)
    │   ├── en/                # English JSON bundles
    │   └── tr/                # Turkish JSON bundles
    └── images/
        ├── category_images/   # Category / subcategory SVGs
        └── script_images/     # Script-related SVGs
```

Clients typically: read **`manifest.json`**, compare hashes or versions to their cache, then fetch only what changed under the **`path`** / **`basePath`** fields.
